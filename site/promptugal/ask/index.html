PrompTugal on Mistral: ask

Ask PrompTugal, on Mistral

Ask about Portugal, in European Portuguese or in English. A Mistral model, called from this page with your own key, answers only from what PrompTugal publishes: the public data on data.promptugal.news (IPMA weather warnings and forecasts, fire risk, sea, events, cyber security) and the pages of PrompTugal.news. It links each source it used and says when the data was read, and says so plainly when PrompTugal's data does not say.

What this page reads, and from where

When the model asks for a tool, your browser reads PrompTugal's public files itself, with a plain GET: no key, no cookies, no question text. Only these addresses, and the content security policy of this page allows no others:

  • https://data.promptugal.news/api/v1/index.json: the catalogue of PrompTugal's data sources.
  • https://data.promptugal.news/api/v1/<source>/latest.json: one source's latest data, for a source named in that catalogue only.
  • https://promptugal.news/api/v1/search/docs.json: PrompTugal.news's own search index (about 240 KB).
  • https://promptugal.news/<page>.md: the text of a page listed in that index only.

PrompTugal is a family of Portuguese news and public-data sites built by AI agents with a named human operator, Dinis Cruz, as its llms.txt says (as read on 21 November 2026): (promptugal.news, data.promptugal.news). Its data is collected by code, twice a day for IPMA's sources, and each file says when it was read (as read on 21 November 2026). IPMA's data may be used without a profit-making purpose only; this demonstration is not commercial. Not a warning service: follow IPMA and the civil protection authority, ANEPC.

Four questions we asked through Mistral's API on 21 November 2026, two in Portuguese and two in English, one of which PrompTugal's data does not answer. Saved as a file on this site, with every tool call and what it read. Replaying sends nothing anywhere.

What happens to a key from a QR code

Opened as a link: the browser never sends the part after "#" to any server, and this page removes it from the address bar and this tab's history the moment it loads. Your camera app or browser may still keep the link in its own history, so treat that link like the key itself. As a picture: decoded with your browser's own QR reader or, where it has none, jsQR, a copy kept on this site. Either way the key goes into the key box above, held in this tab's memory only, and is never shown.

What we found in our own runs

Two recorded runs of the same four questions on mistral-small-2603 through api.mistral.ai, 21 November 2026, on PrompTugal data read at 18:04 to 18:15 UTC on 20 November. n = 2 runs, 8 answers: a small sample, not a benchmark.

  • First run (01:55 UTC, temperature not set; the file): asked about warnings for Lisbon, the model read the one row for Lisboa (yellow, rain, 12:00 to 18:00 on 21 November) and then answered "Não há avisos meteorológicos ativos para Lisboa." That is wrong. In the same run it gave a read time of "16:40 UTC" for news pages that no tool gave: the figure check above flags exactly that kind of number. And its refusal described what PrompTugal publishes from nothing the tools returned.
  • So we changed three things: the prompt says rows returned are the answer and a read time must come from a tool, read_news now gives the time it read the page, and the temperature is 0.
  • Second run (the replay above): the Lisbon warning right, every figure in the four answers found in what the tools read, the refusal plain. One miss the figure check cannot see: asked which vulnerabilities CISA added most recently, it named three vendors for 18 November, but the data has four entries that day (the fourth is Vanderbilt University's REDCap).

Checking figures in code catches an invented number; it does not catch a missing one, or a true number put in the wrong place. Read the sources.

How it works, and what it does not claim

  • Four tools, in pt-tools.js: list_sources, read_source (one source, one part of it, the rows that contain a word), search_news and read_news. They follow PrompTugal.news's own json-tools.js (Apache-2.0). The model never gives an address: it names a source from the catalogue or a page from the index, and the address is built in code.
  • The tool loop is PrompTugal.news's chat-core, ported to Mistral for Ask this site, reused unchanged: chat-core.js. The key panel is that page's panel.js, unchanged. PrompTugal.news's own chat runs on OpenRouter (its default model is anthropic/claude-sonnet-5, in chat-core.js, as read on 21 November 2026); here the brain is Mistral's.
  • Each number, time and date in an answer is looked for, in code, in what the tools returned for that answer (figcheck.js), and marked found or not found.
  • Every tool result goes back to the model inside <untrusted-data> markers, with the instruction that it is material, never instruction. A link in an answer becomes clickable only if a tool returned that exact address.
  • The model is told to answer only from the tools, in European Portuguese (not Brazilian) or in English, and to give each figure as the data gives it. It can still be wrong: open the sources and check. The answers are model output.
  • This page talks to four places only: this site, the Mistral endpoint you choose (with your key, when you press Ask), data.promptugal.news and promptugal.news (without your key). Its content security policy enforces that.
