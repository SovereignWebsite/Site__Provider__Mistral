In your browser

Seal a key for a browser

Open this on the device that holds your Mistral key. It encrypts the key, in this tab, with another browser's public key, so that only that browser can open it. Nothing is sent anywhere and nothing is stored.

1. The browser you are sealing for

Scan the code on that browser's key pair page, or paste its public key here.

Its fingerprint

Compare this with the fingerprint shown on the browser you mean to send to. If they differ, stop: someone could have sent you their own public key, and a key sealed to it would be theirs to open.

2. Your Mistral key

It is read once from the box, which is cleared at once, sealed in this tab, and not kept: not shown again, not stored, not sent.

Only seal for a browser you can see in front of you. Check that the fingerprint on both screens is the same.

If your browser offers to save this key as a password, choose Never.

3. The sealed key

Open this link in the browser with that fingerprint: scan the code with it, or copy the text across. That browser stores it as it is, and opens it only when you ask.

A photograph of this code is useless to anyone else. It holds only ciphertext, which nothing can open except the private key inside the browser it was sealed for, and that key cannot be copied out of it. That is the gain over the code on the team page, which carries the plain key: anyone who sees that one has your key.

What sealing protects, and what it does not

  • Only the browser you seal for can open it. Its private key was made not extractable, so it cannot be copied out of that browser, and what that browser stores is only ciphertext.
  • But any script running on mistral.provider.sovereignweb.site can ask that browser to unwrap the key and use it. Every page of this site shares one origin, and so one key store. This site loads no script from anywhere else and every page has a strict content security policy, but that is the line.
  • So can anyone using that browser profile, or anyone who copies it.
  • So: use a Mistral key with a spending limit, revoke it after the event, and on a shared machine press "Forget this browser's keys" on its key pair page when you are done.
  • Clearing that site's data, or a private window, loses the key pair and the sealed key there. Seal the key again for its new key pair.

How the sealing works

  1. The public key comes in the part of the link after #, which browsers do not send to any server, or as pasted text. This page removes it from the address bar, then checks that the key pair was made on this same site, that its fingerprint (SHA-256 of the key's SubjectPublicKeyInfo bytes, first 16 hex characters) matches the key, and that the key is RSA-OAEP 3072-bit. A public key from any other site is refused.
  2. When you press Seal, Web Crypto makes a fresh AES-256-GCM key and a random 12-byte nonce, encrypts your Mistral key with them, and wraps the AES key with RSA-OAEP (SHA-256) under that public key. The AES key and your plain key are then dropped.
  3. The result is {v:2, origin, fp, created, expires, wrapped, iv, ct} in base64url, shown as a link to /browser/keys/ with it after #sealed=. The origin, fingerprint, creation time and expiry are bound to the ciphertext as AES-GCM additional data, so changing any of them makes it impossible to open. The browser it is for refuses it after it expires (2, 8 or 24 hours, your choice) and deletes it.
  4. This page makes no request of any kind, and its content security policy allows none to anywhere but this site.

Sealing code: vault.js, adapted from AgentiCCells__Site__Evals (Apache-2.0). QR codes: Kazuhiko Arase's qrcode-generator (MIT), at /team/qrcode.js.
